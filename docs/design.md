## 1. 全体構成

サーバーを持たない静的サイト。計算・表示はすべてブラウザ内で行う。

```
ブラウザ
├─ 画面（React）
│   テンプレート一覧 → 回路図・パラメータ入力 → 解析実行 → グラフ／数値・解説
│        │                                  ▲
│        │ ネットリスト（文字列）             │ 解析結果（数値配列）
│        ▼                                  │
└─ Web Worker（別スレッド）
    eecircuit-engine（ngspice の WebAssembly 版）
```

- テンプレートは「部品値 → ngspice ネットリスト」を作る関数を持つ。画面は部品値を集めるだけで、
  回路の中身を知らない（入出力とロジックの分離）
- ngspice は計算中に画面を止めてしまうため、Web Worker で動かす
- データベース・ログイン・外部 API はない。外部へ送る通信もない
- Service Worker（PWA）がアプリ一式と計算エンジンを端末に保存し、2 回目以降はオフラインでも動く

### PWA

- インストール: マニフェスト（アプリ名・アイコン・テーマ色）を用意し、PC（Chrome / Edge）と
  スマホ（Android の Chrome、iPhone の Safari「ホーム画面に追加」）でアプリとして起動できるようにする
- オフライン: ビルドで出力されるファイル（画面・計算エンジン・解説・アイコン）をすべて事前キャッシュする
  - Workbox は既定で 2MB を超えるファイルをキャッシュしないため、上限を 30MB に引き上げる（計算エンジン 約 20MB のため）
  - 計算はもともと端末内で完結するので、キャッシュさえあればすべての機能がオフラインで使える
- 更新: 新しいバージョンを公開すると、次に開いたときに「新しいバージョンがあります［更新］」と表示し、
  押すと切り替える（自動で切り替えると、操作中に画面が再読み込みされるため）
- 注意: iPhone では、ホーム画面に追加せずブラウザで使っている場合、しばらく使わないとキャッシュが
  消されることがある。その場合は再ダウンロードされるだけで、動作に問題はない

## 2. 技術スタック

| 用途 | 採用 | 理由 |
|------|------|------|
| 画面 | TypeScript + React（Vite） | 画面の状態（部品値・解析結果）が多いため。tech-stack.md の「動的な画面が多い場合」の推奨 |
| 計算エンジン | eecircuit-engine 1.8.0（MIT） | ngspice を WebAssembly 化した npm パッケージ。ネットリスト文字列を渡すと結果の数値配列が返る |
| グラフ | uPlot（MIT） | 軽量（約 50KB）で、パワエレ系の数万点の波形も速く描ける |
| 解説文 | Markdown（marked）＋数式 KaTeX（いずれも MIT） | 34 種の解説を書きやすく、設計式をきれいに表示できる |
| PWA | vite-plugin-pwa 2.x（MIT、内部で Workbox を使用） | Service Worker とマニフェストをビルド時に自動生成できる |
| テスト | Vitest | Vite と設定を共有できる |
| 公開 | GitHub Pages ＋ GitHub Actions | 無料で公開回数の上限が実質ない（tech-stack.md の標準 Netlify から変更。2026-10-21 決定） |

### 計算エンジンの調査結果

- eecircuit-engine: 2026-09-05 に 1.8.0 を公開、週次でプレビュー版も出ており継続開発中
- 使い方: `start()` で初期化 → `setNetList(ネットリスト)` → `runSim()` で結果
  （変数名・種類〔電圧/電流/時間/周波数〕・数値配列。AC 解析は複素数）
- サイズ: 本体 約 20MB（圧縮転送で 約 5.7MB）。初回だけダウンロードし、以降はブラウザのキャッシュを使う
- 本体は画面と同じスレッドで動く作りのため、自前の Web Worker で包む
- 検証結果（2026-10-21、PC の Node.js とブラウザ。`npm run verify:engine` で再現できる）:
  - Worker 内での動作: 開発サーバー・製品ビルド（`/circuit-lab/` 配下）の両方で動作。初期化＋解析で 約 0.7〜1.2 秒
  - 精度: RC フィルタのカットオフ -3.01dB（理論 -3.01）、RC 充電 1ms で 0.6346V（理論 0.6321）
  - 降圧コンバータ（12V・デューティ 50%）: 300 周期・約 4 万点で 0.26 秒。出力 5.74V
    （理論 6V との差は、ダイオードの順方向電圧とスイッチのオン抵抗による損失）
  - 三相インバータ（300V・50Hz・2 周期）: 0.03 秒。線間電圧の最大 300.1V（理論 300V）
  - 速度は PC での値。パワエレ系でも十分速いため、スマホでの許容 10 秒には余裕がある見込み
- 【未検証】スマホ実機での読み込み時間・動作、PWA で計算エンジン（約 20MB）をキャッシュして
  オフラインで動くか（特に iPhone）。PWA 化の実装後に確認する

## 3. データ設計

データベースは持たない。保存機能も v1 では持たない（要件のスコープ外）。
アプリ内のデータはテンプレート定義（ソースコード）だけ。

### テンプレート定義（`src/templates/<分類>/<回路ID>/index.ts`）

| 項目 | 型 | 説明 |
|------|----|------|
| id | string | 回路 ID。URL にも使う（例: `rc-lowpass`） |
| category | Category | 分類（basic / transient / filter / power-supply / transistor / opamp / power-electronics） |
| title | string | 表示名（例: 「RC ローパスフィルタ」） |
| summary | string | 一覧に出す 1 行説明 |
| params | ParamDef[] | 調整できる部品値の一覧（下表） |
| analyses | AnalysisDef[] | このテンプレートで使える解析（DC / 過渡 / AC）と、表示する信号 |
| buildNetlist | (値) => string | 部品値から ngspice ネットリスト（解析命令を除く本体）を作る |
| schematic | SchematicDef | 回路図の部品配置と配線 |
| explanation | string | 解説文（同じフォルダの `explanation.md` を読み込む） |

### 部品値の定義（ParamDef）

| 項目 | 型 | 説明 |
|------|----|------|
| key | string | ネットリスト内で使う名前（例: `R1`） |
| label | string | 表示名（例: 「抵抗 R1」） |
| unit | string | 単位（Ω, F, H, V, Hz, %, s） |
| default / min / max | number | 初期値と許容範囲。範囲外は解析を実行しない |
| scale | 'linear' \| 'log' | スライダーの目盛り。抵抗・容量のように桁が変わる値は log |

### 解析の定義（AnalysisDef）

| 項目 | 型 | 説明 |
|------|----|------|
| kind | 'op' \| 'tran' \| 'ac' | 直流動作点 / 過渡 / 周波数特性 |
| command | (値) => string | 解析命令（例: `.tran 1u 5m`）。部品値に応じて時間範囲を変えられる |
| probes | ProbeDef[] | 表示する信号。名前・単位と、結果からの計算方法（例: `v(out)`、線間電圧 `v(u) - v(v)`） |
| autoRun | boolean | 値の変更で自動的に再計算するか。パワエレ系は false |

### 内蔵部品ライブラリ（`src/models/`）

すべて自作パラメータの汎用モデル（型番メーカーのモデルを複製しない。再配布の権利関係を避けるため）。

| 部品 | モデル |
|------|--------|
| 汎用ダイオード / 整流ダイオード | ngspice 標準のダイオードモデル |
| ツェナーダイオード（5.1V など） | ダイオードモデル（逆耐圧 BV を設定） |
| LED（赤） | ダイオードモデル（順電圧 約 2V になるよう設定） |
| NPN / PNP トランジスタ | ngspice 標準の BJT モデル（小信号汎用品相当） |
| N チャネル MOSFET | ngspice の VDMOS モデル（パワー MOSFET 相当） |
| オペアンプ | 自作のサブサーキット（直流利得・利得帯域幅積・出力の電源電圧制限を持つ） |
| 理想スイッチ | ngspice 標準の電圧制御スイッチ（オン抵抗・オフ抵抗のみ） |

## 4. 処理設計

### 解析の実行

- 入力: テンプレート、部品値、解析の種類
- 処理の流れ:
  1. 部品値を検証（数値であること・min〜max の範囲内）
  2. `buildNetlist(値)` ＋ 部品ライブラリ ＋ `command(値)` でネットリストを組み立てる
     （ネットリストに入るのは検証済みの数値だけ。自由入力の文字列は入れない）
  3. Worker へ送信 → ngspice 実行 → 結果を受信
  4. probes に従って表示用の値に変換（AC はゲイン [dB] と位相 [°] に変換）
  5. グラフ（過渡・AC）または表（DC）に表示
- 異常時の扱い:
  - 範囲外の値: 入力欄に「◯〜◯ の範囲で入力してください」と表示し、実行しない
  - ngspice のエラー（収束しない等）: 「計算が収束しませんでした。値を変えて再実行してください」と、
    ngspice のメッセージを折りたたみで表示
  - 30 秒を超えたら Worker を止めて作り直し、「計算に時間がかかりすぎたため中止しました」と表示
  - エンジン読み込み失敗: 「計算エンジンを読み込めませんでした。再読み込みしてください」

### 値の変更と再計算

- 自動実行のテンプレート: 値の変更から 0.4 秒待って実行。実行中に変わった場合は、終わってから最新の値で 1 回だけ再実行
- パワエレ系: 「実行」ボタンを押したときだけ実行

### 数値の入力と表示

- SI 接頭辞で入力・表示できる（`4.7k`, `100n`, `2.2u`）。変換処理は `src/engine/units.ts` にまとめる

### 電流の測定

ngspice は電圧源の電流しか直接出さないため、電流を見たい枝には 0V の電圧源（電流計の代わり）を
テンプレート側で入れておく。

## 5. API 設計

なし（サーバーを持たない）。

画面と Worker 間のメッセージ:

| 向き | type | 内容 |
|------|------|------|
| 画面 → Worker | `run` | 実行 ID、ネットリスト |
| Worker → 画面 | `ready` | エンジンの初期化完了 |
| Worker → 画面 | `result` | 実行 ID、解析結果 |
| Worker → 画面 | `error` | 実行 ID、エラーメッセージ |

実行 ID で、古い実行の結果が後から届いても捨てられるようにする。

## 6. 画面設計

1 画面のアプリ。URL の `#/<回路ID>`（例: `#/rc-lowpass`）で表示する回路を切り替える
（ブックマーク・ブラウザの戻るが使える）。

| 領域 | 内容 |
|------|------|
| テンプレート一覧 | 分類ごとに 34 種を表示。PC は左側に常時表示、スマホは上部のボタンで開閉 |
| 回路図 | SVG で描画。部品記号の横に部品名と現在の値を表示 |
| 部品値パネル | 部品ごとにスライダー＋数値入力 |
| 解析タブ | そのテンプレートで使える解析（DC / 過渡 / AC）だけを表示。パワエレ系は「実行」ボタン付き |
| 結果 | 過渡: 時間波形（信号ごとに表示の切替）。AC: ボード線図（ゲインと位相の 2 段）。DC: ノード電圧・電流の表 |
| 解説 | 動作原理・設計式・使いどころ |
| フッター | 使用しているオープンソースのライセンス表記（ngspice ほか） |

- PC: 左に一覧、右に「回路図＋部品値」と「結果」を並べ、その下に解説
- スマホ: 回路図 → 部品値 → 結果 → 解説 の縦並び
- グラフの拡大・縮小、カーソルで値を読む（任意機能）は uPlot の標準機能で対応する

### 回路図の描き方

34 種の回路図を 1 枚ずつ絵として描くと修正が大変なため、テンプレートには
「部品記号の種類・位置・向き」と「配線の折れ線」だけを書き、共通の描画部品が SVG にする。

## 7. フォルダ構成

```
src/
├─ main.tsx, App.tsx       画面の入口
├─ components/             画面部品（一覧・回路図・部品値パネル・グラフ・解説）
├─ engine/                 計算まわり（Worker・ネットリスト組み立て・結果の変換・単位変換）
├─ models/                 内蔵部品ライブラリ
├─ schematic/              回路図の部品記号と描画
└─ templates/              回路テンプレート（分類ごとのフォルダ、回路ごとに index.ts と explanation.md）
tests/                     Vitest のテスト
```

## 8. テスト方針（詳細はテスト工程で決める）

- 単体テスト: 単位変換、部品値の検証、全テンプレートのネットリスト生成、結果の変換
- 計算の確認: 代表的な回路を実際に ngspice で解き、理論値と比べる（完成条件の確認）
  - 分圧比、RC フィルタのカットオフ周波数（-3dB）、オペアンプのゲイン、降圧コンバータの出力電圧（≒ 入力 × デューティ比）
- 画面: ブラウザで PC 幅・スマホ幅を確認

## 9. 公開・運用

- 公開先: GitHub Pages。main に push すると GitHub Actions がビルドして自動で公開する
  - URL: `https://<GitHub ユーザー名>.github.io/circuit-lab/`（独自ドメインは使わない）
  - サブパスで公開されるため、Vite の `base` とマニフェストの `scope` / `start_url` を `/circuit-lab/` にする
  - ビルド: `npm run build`、公開フォルダ: `dist`（docs/ や tests/ は公開されない）
  - URL は `#/<回路ID>` 方式なので、GitHub Pages で起きがちな「ページを再読み込みすると 404」は起きない
  - GitHub Pages は HTTP ヘッダを設定できないため、deploy-targets.md の安全側ヘッダは付けられない。
    代わりに HTML の meta タグで Content-Security-Policy を設定する（WebAssembly の実行に必要な
    `'wasm-unsafe-eval'` を許可する）
- ランニングコスト: 0 円（要件「すべて無料」を満たす。2026-10-21 確認）
  - GitHub Pages・GitHub Actions は Public リポジトリなら無料。有料プランへの自動切り替えはない
  - 制限（目安）: サイト容量 1GB まで（本アプリは 約 25MB）、転送 月 100GB 程度、ビルド 1 時間 10 回程度。
    超えても課金はされない。PWA のキャッシュで 2 回目以降はほぼ転送しないため、自分だけの利用なら十分収まる
- リポジトリを Public にするため、push 前にコミット履歴に秘密情報・個人情報がないことを確認する
- 他にかかる費用: なし（下表）

| 使うもの | 費用 | ライセンス・条件 |
|----------|------|------------------|
| GitHub（リポジトリ・Pages・Actions） | 無料 | Public リポジトリ |
| vite-plugin-pwa・Workbox | 無料 | MIT |
| Node.js・Vite・React・Vitest | 無料 | MIT など |
| eecircuit-engine | 無料 | MIT |
| ngspice（エンジン内部） | 無料 | 修正 BSD（一部 LGPLv2 など）。ライセンス表記が必要 |
| uPlot・marked・KaTeX | 無料 | MIT |
| 外部 API・有料サービス | 使わない | ― |
- ログ / 失敗時の気づき方: 個人利用のため収集しない。画面上のエラー表示で気づく
- 戻し方: 問題のあるコミットを `git revert` して push する（自動で前の状態が公開される）
- ライセンス: リポジトリは MIT。使用ライブラリのライセンスを画面のフッターに表記する

## 10. 実装の進め方

リスクの大きい計算エンジンから先に確かめる。

1. Vite 雛形を作り、Worker で ngspice を動かす（RC ローパスの AC・過渡、降圧コンバータ、三相インバータで速度も確認）
2. 共通の画面（一覧・回路図・部品値・グラフ・解説）と代表 5 種のテンプレート
3. 残りのテンプレートを分類ごとに追加
4. PWA 化、テスト、スマホ幅の確認、GitHub Pages で公開
